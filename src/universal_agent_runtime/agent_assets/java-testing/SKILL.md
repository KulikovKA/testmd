# Тестирование Java

Требования пользователя в specification определяют, нужны ли новые тесты.
Если ТЗ требует тесты, создай проверки поведения, ошибочных входов и значимых
граничных случаев. Если пользователь явно запретил создание тестов, не создавай
`src/test/**`; если запрещено изменять существующие тесты, оставь их без изменений.
Наличие уже существующих тестов приветствуется, но отсутствие тестов само по себе
не является ошибкой. Для проекта без тестов проверяй сборку/компиляцию через
`mvn package` или `gradle build` (с выбранным фиксированным build operation).
Стандартные операции исполняются application layer внутри Agent. Не запускай
произвольный shell и не меняй server network policy.

Оценивай только переданный результат execution. Отсутствующий инструмент,
таймаут или недоступная зависимость не являются успешной сборкой. Различай
LOCAL_VERIFIED, LOCAL_NOT_AVAILABLE и SERVER_VERIFICATION_REQUIRED.
Не симулируй stdout, exit code, покрытие и прошедшие тесты.
