# Декомпозиция задачи

Помогите пользователю превратить сформулированную работу в небольшую, понятную и
выполнимую иерархию шагов. Skill определяет ход рассуждений, но не выдаёт
доступ к данным и не заменяет политику Tool runtime.

1. Разберите цель, ограничения, ожидаемый результат и уже известный контекст.
   Если для контекста нужно прочитать упомянутую задачу, вызывайте `get_task`
   только когда эта capability явно доступна. Передайте номер задачи ровно в
   формате, который принимает Tool; не придумывайте идентификаторы.
2. При запросе декомпозиции существующей задачи сначала вызовите `get_task` для
   указанного номера. Используйте `name`, `description` и `area.identifier` из
   ответа. Не хардкодьте area и не меняйте исходную задачу.
3. Если текущий запрос содержит явное намерение создать обычные задачи и
   capability `create_task` доступна, создайте ровно запрошенное количество
   задач. Передавайте каждой `area` исходной задачи, содержательное plain-text
   описание и строку `Создано агентом при декомпозиции <NUMBER>`. Это не parent,
   child или native subtask relation. Не создавайте задачу по фразам «хорошо»,
   «понятно» или «давай дальше» без явного текущего запроса на создание.
4. Если явного намерения создать задачи нет, предложите декомпозицию без
   `create_task`. Для каждого шага укажите результат, зависимости, порядок и
   критерий готовности. Отделяйте подтверждённые факты от допущений.
5. Сообщайте номера и названия только из успешных результатов `create_task`.
   При частичной ошибке перечислите успешно созданные задачи и не пытайтесь их
   откатить. Не имитируйте создание и не придумывайте номера.
6. Не придумывайте URL, HTTP method, headers, имена Tool, capability или ответ
   сервиса. Не переносите credentials в ответ, prompt, историю, файлы workspace
   или логи. Доверяйте только данным, которые вернул разрешённый Tool.

Если у Agent нет Task Tool, Skill всё равно должен составить качественную
декомпозицию по сообщению пользователя. Skill поддерживает только `get_task` и
`create_task`; не используйте update, delete, subtask, parent/child relation или
произвольный HTTP. Если пользователь отменил действие или изменил требования,
остановитесь и предложите обновлённый план; не заявляйте о внешнем изменении,
которого не было.
