# Декомпозиция задачи

Помогите пользователю превратить сформулированную работу в небольшую, понятную и
выполнимую иерархию шагов. Skill определяет ход рассуждений, но не выдаёт
доступ к данным и не заменяет политику Tool runtime.

1. Разберите цель, ограничения, ожидаемый результат и уже известный контекст.
   Если для контекста нужно прочитать упомянутую задачу, вызывайте `get_task`
   только когда эта capability явно доступна. Передайте номер задачи ровно в
   формате, который принимает Tool; не придумывайте идентификаторы.
2. При запросе декомпозиции существующей задачи сначала вызовите `get_task` для
   указанного номера. Используйте `name`, `description` и `area.identifier` из
   ответа. Не хардкодьте area и не меняйте исходную задачу.
3. Создавать дочерние задачи при декомпозиции можно только для Epic. До любой
   mutation убедитесь, что `type` исходной задачи строго равен
   `epic`. Если это не Epic, не вызывайте `create_task` или `add_child_task` и
   ясно сообщите, что дочерняя декомпозиция поддерживается только для Epic.
4. Если текущий запрос содержит явное намерение создать декомпозицию или
   дочерние задачи и capabilities `create_task` и `add_child_task` доступны,
   сначала составьте план, затем создайте ровно запрошенное количество обычных
   задач. Передавайте каждой `area` исходного Epic, содержательное plain-text
   описание и строку `Создано агентом при декомпозиции <NUMBER>`. После каждого
   успешного `create_task` используйте полученный реальный номер в
   `add_child_task` с `parent_epic` исходного Epic и `child_task` созданной
   задачи. Фраза «исходную задачу не изменяй» не отменяет создание дочерних
   задач; она запрещает изменять сам Epic. Не создавайте задачу по фразам
   «хорошо», «понятно» или «давай дальше» без явного текущего запроса на
   создание.
5. Если явного намерения создать задачи нет, предложите декомпозицию без
   `create_task` и `add_child_task`. Для каждого шага укажите результат,
   зависимости, порядок и критерий готовности. Отделяйте подтверждённые факты
   от допущений.
6. Сообщайте номера и названия только из успешных результатов `create_task`, а
   дочернюю связь — только из успешного результата `add_child_task`. При
   частичной ошибке перечислите успешно созданные и отдельно успешно привязанные
   задачи. Продолжайте независимые привязки остальных уже созданных задач, но не
   откатывайте и не создавайте повторно уже успешные задачи. При повторной
   попытке используйте только непривязанные номера. Не имитируйте создание или
   связь и не придумывайте номера.
7. Не придумывайте URL, HTTP method, headers, имена Tool, capability или ответ
   сервиса. Не переносите credentials в ответ, prompt, историю, файлы workspace
   или логи. Доверяйте только данным, которые вернул разрешённый Tool.

Если у Agent нет Task Tool, Skill всё равно должен составить качественную
декомпозицию по сообщению пользователя. Skill поддерживает только `get_task`,
`create_task` и `add_child_task`; не используйте update, delete, произвольную
связь или произвольный HTTP. Если пользователь отменил действие или изменил
требования, остановитесь и предложите обновлённый план; не заявляйте о внешнем
изменении, которого не было.
