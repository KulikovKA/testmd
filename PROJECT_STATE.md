## Работающая функциональность

Проверено в рамках TASK-002:

- `AgentRuntime` — это принадлежащий приложению асинхронный протокол для create/start/status/stop/delete.

- Принадлежащие домену `AgentId`/`WorkspaceId` валидируют идентификаторы, не принимая пути.

Неизменяемые запросы содержат явные требования к workload, workspace, ресурсам, окружению,

ссылкам на секреты и сетевому доступу с политикой запрета по умолчанию.

- `RuntimeHandle` является непрозрачным и привязанным к Agent. `RuntimeObservation` отделяет

выполнение от готовности и от принадлежащего Orchestrator состояния жизненного цикла Agent.

- `RuntimeFailure` предоставляет безопасные метаданные operation/Agent/category/retry и

необязательный recovery handle, без backend-объектов или произвольного текста исключений.

- Тестовый fake и общий набор тестов проверяют идемпотентность, конфликты владения,

готовность, сохранение workspace при stop/start, удаление, отмену, дедлайны,

неопределённые результаты и восстановление после частичной очистки create/delete.

- Существующий smoke-тест импорта пакета/неактивной композиции продолжает проходить.

- Backlog по-прежнему содержит 21 задачу и исходные критерии приёмки;

итоговое количество статусов: 3 `DONE`, 18 `TODO`, 0 `ACTIVE` и 0 `BLOCKED`.

Реальное применение ограничений ресурсов/сети, надёжное восстановление, оркестрация Agent, непрерывность

сессии Qwen, inference, Tools, Skills, DockerRuntime и KataRuntime имеют статус

`NOT VERIFIED`: для них требуются последующие задачи реализации/интеграции. Успешно пройденный

in-memory набор контрактных тестов не является доказательством работы реального backend.

## Текущая архитектура

Целевой control plane представляет собой доступный по HTTP Agent Orchestrator, чья логика приложения

зависит от принадлежащих проекту портов. Реализованная управляющая граница находится в

`application/ports/agent_runtime.py`; нейтральные значения/ошибки расположены рядом с ней.

Доменные идентификаторы зависят только от стандартной библиотеки. В коде domain/application отсутствуют

импорты инфраструктуры и ветвления по backend.

Драйверы отвечают за отображение непрозрачных ссылок на backend-ресурсы и метаданные восстановления.

Create является идемпотентным по идентификатору Agent на протяжении его жизненного цикла; успешный

delete завершает жизненный цикл этого идентификатора. Операции, завершившиеся по timeout или отмене,

могут фактически применить изменения, поэтому вызывающая сторона выполняет согласование/повтор с тем же

идентификатором. При частичной очистке владение сохраняется до её завершения. Fake реализует это только

в памяти.

`ExecutionState` и `Readiness` являются наблюдениями среды выполнения, а не состояниями жизненного

цикла Agent. Подтверждённая готовность требует независимого сигнала уровня агента.

Только Orchestrator определяет состояние Agent и допускает выполнение turn. Обмен conversation/session

остаётся отдельным будущим портом; TASK-002 не придумывает для него протокол.

Каждый Agent по-прежнему владеет одной runtime, Workspace, логической Session, конфигурацией,

Skills и ограниченными Tools. Qwen Code планируется размещать внутри runtime; Ollama

остаётся внешним и настраиваемым. Декомпозиция задач остаётся конфигурируемым поведением.

См. [architecture.md](docs/architecture.md) и

[контракт среды выполнения](docs/runtime-contract.md) для точной семантики и границ области ответственности.

## Известные проблемы

- Унаследованный Git-репозиторий домашней директории включает несвязанные пользовательские файлы.

Не использовать repository-wide add, clean, format, reset или другие разрушительные операции.

Решение о создании локального для проекта репозитория по-прежнему требует указания пользователя.

- Реальное соответствие Docker/Kata контракту, изоляция сети, ограничения ресурсов, обработка удалённых race-condition

и crash durability имеют статус `NOT VERIFIED` до выполнения соответствующих задач драйверов.

- Fake сохраняет данные о владении и удалении только на протяжении жизни своего тестового экземпляра.

Production-адаптеры должны сохранять достаточное состояние для recovery/idempotency.

- Тесты содержимого Workspace используют синтетические данные в памяти; фактическое сохранение сессии

имеет статус `NOT VERIFIED` до выполнения задач интеграции Qwen/session.

- Пока отсутствует команда запуска продукта, HTTP API или реализованный interaction port.

- Предыдущие частичные переводы документации на русский оставлены без изменений; перевод

оставшейся документации не входит в область TASK-002.

том же event loop. Перед реализацией harness см. `docs/runtime-contract.md`.
